# Запуск замеров (пилот и кампания r3)

Инструкция для того, кто снимает данные на устройствах пула: Mac (Apple M4,
macOS) и Windows (AMD Ryzen 5 3550H). Одна команда делает всё от начала до
конца: готовит стенд и ОС, снимает серии, возвращает настройки. Что и зачем
измеряется — `nir3-spec.md`; формат данных — `docs/DATA.md`.

Порядок работ:

1. **Пилот** — по одному браузеру на каждой машине: оценка разброса между
   прогонами.
2. **Расчёт числа повторов** по пилоту и фиксация его в коде (коммит).
3. **Кампания r3** на обеих машинах — основные данные.

## Что снимается

| Устройство | Пилот (`pilot`) | Кампания (`r3`) |
|---|---|---|
| Mac | Chromium S1–S5 | Chromium S1–S5, Firefox S1–S5, WebKit S2–S4 |
| Windows | Firefox S1–S5 | Chromium S1–S5, Firefox S1–S5 |
| Время | ≈ 1,3 ч на машину | Mac ≈ 12 ч, Windows ≈ 9,5 ч |

Делить можно как угодно: прерванная кампания продолжается той же командой,
готовые серии пропускаются. Например, кампанию r3 — на две ночи:
`--filter chromium` в первую, остальное во вторую.

## 1. Один раз на каждом устройстве

```bash
git clone <репозиторий> && cd benchmark        # или git pull
git switch nir3-protocol
npm install
npm run browsers        # сборки браузеров пула: Chromium 153, Firefox 155, WebKit 26.6
```

**macOS.** Заведите отдельную учётную запись для замеров, без iCloud,
объектов входа и лишних приложений. Кампанию запускайте из неё.

**Windows.** Сделайте «чистую загрузку» (её откат — те же шаги в обратную
сторону):
1. `Win+R` → `msconfig` → «Службы» → «Не отображать службы Майкрософт» →
   «Отключить все».
2. Диспетчер задач → «Автозагрузка» → отключить всё.
3. Перезагрузка.

## 2. Перед каждым запуском

Кампания спросит эти пункты и запишет ответы в журнал, но подготовить их
нужно заранее:

- [ ] зарядка подключена; macOS — режим энергосбережения выключен; Windows —
      «Параметры → Система → Питание» → «Максимальная производительность»;
- [ ] все приложения закрыты (IDE, браузеры, мессенджеры, облачные клиенты,
      утилиты производителя, оверлей AMD);
- [ ] macOS: вы в учётной записи для замеров, основная — **завершена**
      (выход, а не быстрое переключение);
- [ ] встроенный дисплей, внешние мониторы отключены, крышка открыта;
- [ ] заставка выключена, блокировка экрана по бездействию не сработает;
- [ ] macOS: «Не беспокоить» включён;
- [ ] в репозитории нет незакоммиченных изменений в коде (`git status`).

## 3. Пилот

Зачем: число повторов на ячейку зависит от того, насколько прогоны одного
и того же варианта отличаются друг от друга. Это разное для разных
сценариев, браузеров и машин, поэтому разброс сначала измеряется.

Пилот снимается на двух платформах — по одному браузеру на машину, разные
движки: **Mac · Chromium** и **Windows · Firefox**.

**Запуск** — как кампания (см. раздел 5), сессия `pilot`:

```bash
scripts/macos/measure.sh pilot                                              # Mac
powershell -ExecutionPolicy Bypass -File scripts\windows\measure.ps1 pilot   # Windows
```

В пилоте на каждую ячейку 5 повторов (S3 — 10: он дешёвый и шумнее), плюс
1 прогревочный прогон, который не сохраняется. Число повторов основной
серии берётся то же и для остальных платформ, включая WebKit.

**После пилота:**

1. Закоммитьте и отправьте данные пилота:
   ```bash
   git add results && git commit -m "pilot: <устройство>" && git push
   ```
2. Число повторов считается ноутбуком `analysis/pilot.ipynb` — он
   воспроизводит весь расчёт из CSV пилота:
   ```bash
   cd analysis && .venv/bin/jupyter nbconvert --to notebook --execute --inplace pilot.ipynb
   ```
   Для каждой ячейки — разброс главной метрики между прогонами; 5 значений
   мало, поэтому берётся его верхняя доверительная граница, и по ней —
   сколько повторов нужно, чтобы различить разницу в 5% (задержка S4 — 10%).
   По сценарию — максимум по двум платформам, но не меньше 10; ячейки с
   двумя устойчивыми уровнями — 30 прогонов.
3. Числа записываются в `packages/harness/src/config.ts`
   (`SCENARIO_DEFAULTS`, поле `repeats`) и в `nir3-spec.md`; изменение
   коммитится. **С этого коммита снимается вся кампания r3.**
4. Данные пилота в выводы не идут; после кампании их можно удалить из
   `results/` (останутся в git).

## 4. Кампания r3

```bash
npm run campaign -- list --session r3     # план и оценка времени
```

Запуск — раздел 5, сессия `r3`. Кампания снимается одним коммитом кода:
если код поменялся между запусками, кампания откажется продолжать.

## 5. Запуск (пилот и кампания)

**macOS** (Терминал, из папки `benchmark`):

```bash
scripts/macos/measure.sh r3 --filter chromium     # ночь 1
scripts/macos/measure.sh r3                       # ночь 2: всё, что осталось
```

**Windows** (обычное окно PowerShell, **не** от администратора, из папки
`benchmark`):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\windows\measure.ps1 r3 -Filter chromium   # ночь 1
powershell -ExecutionPolicy Bypass -File scripts\windows\measure.ps1 r3                    # ночь 2
```

Что будет происходить:

1. Проверка кода, установка браузеров, typecheck, сборка (1–2 мин, нужна сеть).
2. Запрос пароля (macOS) или окно UAC (Windows) — подготовка ОС: выключаются
   индексация, обновления, App Nap / power throttling, сеть (Wi-Fi или
   адаптеры). Исходное состояние сохраняется.
3. Вопросы чек-листа — отвечайте `y` на каждый. На любое «нет» кампания не
   начнётся.
4. **10 минут ничего не происходит** — это нужная пауза без нагрузки.
5. Серии идут одна за другой; окна браузера открываются и закрываются сами.
   Перед каждой серией проверяется паритет сцен — при расхождении серия не
   снимается. **Не трогайте машину** до конца: мышь, клавиатура и другие
   окна искажают замеры.
6. В конце настройки ОС возвращаются. На Windows для этого снова появится
   окно UAC — подтвердите, когда вернётесь.

## 6. Как проверить результат

```bash
npm run campaign -- list --session r3     # ✓ — снято, … — прервано, · — не начато
```

- Данные серии: `results/<устройство>/<браузер>/<сценарий>/r3 <время>/` —
  `manifest.json` и `runs/*.csv` (формат — `docs/DATA.md`). Серия
  завершена, если в manifest заполнено поле `finished`.
- Журнал: `results/<устройство>/journal-r3.md` — чек-лист, начало и конец
  каждой серии, ошибки. Сюда же вручную дописывайте всё необычное
  (например, «в 03:10 машина была разбужена»).

После каждой ночи закоммитьте и отправьте данные:

```bash
git add results && git commit -m "r3: <устройство>, <что снято>" && git push
```

## 7. Если что-то пошло не так

| Ситуация | Что делать |
|---|---|
| Остановили по Ctrl+C / серия упала | Настройки ОС вернутся сами. Запустите ту же команду — снимутся только недостающие серии; прерванная серия снимается заново целиком |
| «Нарушены условия эксперимента …» | Серия остановлена: страница не в production-сборке, без изоляции, с ошибками и т. п. Запишите сообщение в журнал и сообщите — без разбора не перезапускать |
| «Паритет сцен нарушен» | Варианты рисуют разные сцены — это ошибка стенда, не съёмки. Сообщите; подробности — в `manifest.json`, поле `parity.issues` |
| Выключилось питание / перезагрузка посреди кампании | Верните настройки: macOS — `sudo scripts/macos/restore-os.sh`; Windows — `scripts\windows\restore-os.ps1` в окне PowerShell от администратора. Затем та же команда запуска |
| «Код не закоммичен» | Закоммитьте изменения. Данные и журнал не мешают — проверяются только `packages/` и `package*.json` |
| «Серия … снята на коммите X, сейчас Y» | Код поменялся посреди кампании. Вернитесь на коммит X (`git switch --detach X`) или начните кампанию заново |
| «chromium … ≠ 153.0.8010.12 из пула» | `npm run browsers`. Если версия поменялась намеренно — это решение о протоколе, не о съёмке |
| «Уже подготовлено (… .os-state …)» | Прошлый запуск не вернул настройки: сначала `restore-os`, потом запуск |
| Нет Wi-Fi / сети после кампании | macOS: `sudo scripts/macos/restore-os.sh`; Windows: `restore-os.ps1` от администратора |
| Firefox не запускается на macOS | Стенд запускает его с отдельной пустой «домашней папкой» (обход ошибки Playwright на macOS 27, microsoft/playwright#42768). Если всё же не стартует — сообщите |

## 8. Чего не делать

- Не менять код, не обновлять браузеры, Playwright и зависимости посреди
  кампании — версии и коммит одни на всю кампанию.
- Не запускать две кампании одновременно и не пользоваться машиной во время
  съёмки.
- Не удалять прерванные серии из `results/` вручную — кампания их
  пересоздаёт, а для разбора сбоев они полезны.
- Не снимать данные через `npm run bench` с `--allow-dirty` — у таких серий
  в manifest `code.clean = false`, в анализ они не идут.
