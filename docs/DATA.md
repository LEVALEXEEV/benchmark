# Формат данных серии (r3)

Описывает, что harness записывает на диск. Метрики (медианы, p99, ёмкость,
фазы) здесь не хранятся — их считает анализ из сырых замеров.

## Папка серии

```
results/<устройство>/<браузер>/<сценарий>/<серия>/
├── manifest.json
└── runs/
    ├── 001_threejs_1.csv
    ├── 002_r3f-ref_1.csv
    └── …
```

- `<устройство>` — `apple-m4`, `amd-ryzen-5-3550h`
- `<браузер>` — `chromium`, `firefox`, `webkit`
- `<сценарий>` — `s1` … `s5`
- `<серия>` — `r3 2026-11-06T10-00-00Z` (кампания + время старта UTC;
  `pilot …` — пилот)

**Имя файла прогона:** `<номер>_<вариант>[_<точка>]_<повтор>.csv`
- номер — порядок выполнения в серии (001, 002, …);
- вариант — `threejs`, `r3f-ref`, `r3f-ref-central`, `r3f-state`,
  `r3f-parent-state`, `r3f-events`; в S3 у R3F один вариант `r3f` (сцена
  статична, способа обновления нет);
- точка — только S1: `A`, `B`, `C`;
- повтор — 1, 2, … внутри ячейки.

Пример: `017_r3f-ref_B_3.csv` — 17-й по счёту прогон серии, R3F ref, точка
B, третий повтор.

Прогревочные прогоны не сохраняются. Номера идут подряд только по
сохранённым прогонам.

## CSV прогонов

Время — в миллисекундах, 3 знака после запятой. Пустая ячейка — значение
недоступно (например, `gpu_ms` в Firefox и WebKit).

### S1, S2 — строка = кадр

```csv
frame,frame_ms,update_ms,render_ms,gpu_ms
1,4.345,0.705,3.390,1.112
2,4.360,0.710,3.395,1.108
3,4.350,0.700,3.400,
…
```

| Колонка | Что это |
|---|---|
| `frame` | номер кадра в окне записи (30 с) |
| `frame_ms` | длительность кадра: от начала этого кадра до начала следующего |
| `update_ms` | логика: анимация объектов (three.js — цикл, R3F — useFrame) |
| `render_ms` | отрисовка: `renderer.render()` на CPU |
| `gpu_ms` | время работы видеокарты на этот кадр (только Chromium; бывает пусто — замер не успел) |

### S3 — одна строка на прогон

```csv
code_ready_ms,render_start_ms,render_end_ms
86.875,213.630,233.640
```

Все отметки — от начала навигации (открытия страницы).

| Колонка | Что это |
|---|---|
| `code_ready_ms` | код приложения загружен и исполнен |
| `render_start_ms` | начало отрисовки первого кадра с полной сценой |
| `render_end_ms` | конец этой отрисовки — **время до первого кадра** |

Этапы для анализа: загрузка кода = `code_ready`; построение сцены =
`render_start − code_ready`; первая отрисовка = `render_end − render_start`.

### S4 — строка = клик

```csv
click,outcome,event_ms,handler_start_ms,handler_end_ms,applied_ms,render_start_ms,render_end_ms
1,ok,1338.955,1342.215,1342.520,1342.520,1342.570,1346.535
2,ok,1589.120,1590.010,1590.300,1595.880,1599.210,1603.150
3,miss,1840.300,1841.020,1841.200,,,
…
```

Все отметки — от начала окна записи.

| Колонка | Что это |
|---|---|
| `click` | номер клика |
| `outcome` | `ok` — отклик отрисован; `miss` — клик не попал в объект; `timeout` — отклика нет за 2 с; `superseded` — следующий клик пришёл раньше отклика |
| `event_ms` | браузер создал событие клика |
| `handler_start_ms` | событие дошло до страницы (первый обработчик) |
| `handler_end_ms` | все обработчики события отработали |
| `applied_ms` | цвет объекта в сцене фактически изменился |
| `render_start_ms` / `render_end_ms` | отрисовка кадра, в котором отклик впервые виден |

Фазы для анализа: очередь = `handler_start − event`; обработка =
`handler_end − handler_start`; обновление React = `max(0, applied − handler_end)`
(если `applied ≤ handler_end`, отклик применён прямо в обработчике);
ожидание кадра = `render_start − applied`; отрисовка = `render_end −
render_start`; **задержка** = `render_end − event`.

### S5 — строка = кадр

```csv
objects,frame,frame_ms
100,1,2.060
100,2,2.055
…
141,1,2.410
…
```

| Колонка | Что это |
|---|---|
| `objects` | число объектов на текущем уровне |
| `frame` | номер кадра внутри уровня (окно записи 3 с) |
| `frame_ms` | длительность кадра |

Уровни: 100, 141, 200, … (×√2) до двух уровней после падения ниже 30 FPS.
На каждом уровне не меньше 60 кадров: на тяжёлых уровнях окно записи
продлевается (не дольше 5 окон).
Ёмкость при 60 / 30 FPS считает анализ.

## manifest.json

Всё служебное о серии. Пример (S4, сокращено):

```json
{
  "series": "r3 2026-11-06T10-00-00Z",
  "scenario": "s4",
  "created": "2026-11-06T10:00:00Z",
  "finished": "2026-11-06T11:02:41Z",

  "device": { "id": "apple-m4", "cpu": "Apple M4", "cores": 10, "memory_gb": 16,
              "os": "macOS 27.0", "gpu": "ANGLE (Apple, ANGLE Metal Renderer: Apple M4)" },
  "browser": { "name": "chromium", "version": "153.0.8010.12",
               "flags": ["--disable-gpu-vsync", "--disable-frame-rate-limit", "…"] },
  "code": { "commit": "abc1234", "clean": true },
  "libs": { "three": "0.186.0", "react": "19.2.8", "@react-three/fiber": "9.7.0",
            "vite": "8.3.0", "playwright": "1.63.0", "node": "22.20.0" },
  "page": { "build": "production", "isolated": true, "timer_resolution_ms": 0.005,
            "canvas": "1280x720", "device_pixel_ratio": 1 },

  "settings": {
    "variants": ["threejs", "r3f-ref", "r3f-events"],
    "repeats": 20, "warmup_runs": 1,
    "order": "random", "order_seed": 1623597536,
    "warmup_ms": 5000, "record_ms": 30000, "pause_ms": 3000,
    "click_interval_ms": 250, "click_seed": 4242, "click_timeout_ms": 2000
  },

  "parity": { "ok": true, "frame_identical": true },

  "runs": [
    { "file": "runs/001_r3f-events_1.csv", "variant": "r3f-events", "repeat": 1,
      "started": "2026-11-06T10:12:03Z" },
    { "file": "runs/002_threejs_1.csv", "variant": "threejs", "repeat": 1,
      "started": "2026-11-06T10:12:41Z" }
  ],
  "retries": []
}
```

| Поле | Что это |
|---|---|
| `finished` | время конца серии; `null` — серия прервана (кампания снимет её заново, в анализ она не идёт) |
| `device.gpu` | видеокарта, как её называет WebGL на странице. Firefox и WebKit скрывают точную модель («Apple M1, or similar», «Apple GPU») — по ним видеокарту не определить |
| `browser.flags` | аргументы запуска Chromium или настройки Firefox; у WebKit пусто |
| `code.clean` | `false` — код не был закоммичен (`--allow-dirty`, только отладка): в анализ не идёт |
| `page` | условия страницы: production-сборка, изоляция, шаг таймера (Chromium — 0,005 мс, Firefox и WebKit — 0,02 мс), размер холста |
| `settings.warmup_runs` | прогревочных прогонов на ячейку — выполнены, но не сохранены |
| `parity` | все варианты нарисовали ту же сцену, что three.js; `frame_identical` — кадры совпали побитово. При расхождении добавляется `issues`, и серия не снимается. В Firefox на сценах с PBR и тенями (S1, S3) `frame_identical` бывает `false` случайно: Firefox рисует ту же сцену немного по-разному от загрузки к загрузке, и three.js не совпадает сам с собой (проверено 2026-10-15). Сцены при этом равны — средние цвета блоков 8×8 совпадают точно |
| `retries` | прогоны, повторённые после сбоя браузера: какой, попытка, ошибка. Пустой список — сбоев не было |

Отличия по сценариям:
- S1 — в `settings.loads` описание точек A, B, C; у прогона поле `load`;
- S3 — в `settings` нет окон записи; добавлен блок
  `"bundles": { "threejs": { "raw_kb": 549.1, "gzip_kb": 138.0 }, "r3f": { … } }`;
- S5 — в `settings`: `levels`, `fps_floor`, `levels_beyond_floor`,
  `min_level_frames`, `level_warmup_ms`, `level_record_ms`.
